# Contributing

Thanks for taking the time to contribute!

## Getting started

- Read the [README](README.md) first.
- Open an issue to discuss non-trivial changes before writing code.
- Keep pull requests small and focused on one concern.

## Development

1. Fork the repository and clone your fork.
2. Create a branch: `git checkout -b fix/description` or `feature/description`.
3. Make your changes; keep the existing code style.
4. Test your changes locally.
5. Commit with a clear message (e.g. `fix: handle empty input`, `feat: add retry`).
6. Push and open a pull request using the template.

## Pull request checklist

- [ ] Read the contributing guidelines
- [ ] Code follows the project style
- [ ] Change tested locally
- [ ] No secrets or credentials introduced
- [ ] No unrelated changes included

## Questions

Open a discussion or an issue: questions are welcome.
