Con una escritura no es suficiente para obtener RCE, buscamos crear una ROP chain y para eso necesitamos varias escrituras. Si hacemos:
- `[fini_array]` = &fini
- `[fini_array+8]` = &main

*\[!] El binario no tiene PIE*

Tenemos una primitiva de escritura arbitraria infinita debido al bucle que se crea: `fini -> main -> fini -> main -> fini...`. Porque `fini` invoca a main, luego a sí misma y así sucesivamente.

Nótese que main tiene una 'defensa' para ejecutar la escritura una sola vez:
```

  cVar1 = DAT_004b9330;

  ...do stuff
```

La comprobación se realiza con el byte de `al`: 
```
                   00401b9b  3c 01                           CMP                  AL,0x1
                   00401b9d  0f 85 92 00                JNZ                    LAB_00401c35
```

No hay de que preocuparse por eso, porque el bucle iterará y llamará a `main` 256 veces más haciendo el valor de 0x04b9330 nuevamente \x01.

La ROP chain es un `execve('/bin/sh',NULL,NULL)` fácilmente replicable debido a que todos los gadgets necesarios se encuentran en el binario y podemos almacenarlo en alguna dirección escribible del mismo. El único problema es pivotear nuestro stack allí. 

Durante el crash RBP apunta a la dirección 0x4b40f0 (fini_array). Si usamos un gadget `leave; ret`, donde en realidad ocurre `mov rsp, rbp; pop rbp; pop rip; jmp rip` pasa que si reemplazamos `fini_array` por fini:
- RBP: 0x4b40f0
- RSP: 0x4b4100 y RIP: main

Entonces escribimos nuestra ROPchain en `0x4b4100` y forzamos su ejecución con `[fini_array]=&leave_ret_gadget`.

```py
    return struct.pack("<Q",addr)
```
