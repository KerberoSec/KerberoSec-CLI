# Less is More

**Category:** Crypto  ·  **Flag:** `ASIS{iZ_1tEr4t10n_5k1p_m4ke5_n0_1nn0c3nT_r3sPonse!!!?}`

## Challenge Description

A single offline artifact: [`less_is_more.txz`](less_is_more.txz), containing the
generator `src/challenge.py` and a large `output.txt` transcript
(≈3 MB JSON). No live service: everything needed to recover the flag is in the transcript.

The scheme is a **LESS-style code-equivalence signature** over `GF(127)`. A 16-byte
AES-GCM "vault" (published as `nonce`/`ct`/`tag`) is encrypted under a key derived from
the 11 secret monomial keys; recovering those keys reconstructs the vault key and decrypts
the flag.

## Initial Analysis

Parameters (from `challenge.py`):

```text
q = 127, n = 548, k = 274
t = 137 signing rounds, w = 79 challenged (opened) rounds
s = 12  -> 11 nonzero secret-key labels
lambda = 16-byte seeds, lvs = 256 seed-tree leaves
```

Structure per transcript:

- `G0 = [I_274 | M]`; the output publishes `M`. Each of the 11 secrets is a monomial
  matrix `Q_m = (p_m, d_m)` (a permutation `p_m` and an invertible diagonal `d_m`); the
  public key `PK_m` is the systematic form `[I | PK_m]` of `G0·Q_m^{-1}`.
- Signing: a GGM seed tree from root `rt` produces one nonce monomial `Q_{t,i}` per round
  `i` via `spm(SHAKE256(leaf_i || salt || LE32(i)))`. The commitment is one SHA3-256 hash
  over the right halves of all 137 systematicized `A_i`.
- The Fiat-Shamir challenge `b = sch(cmt)` is a shuffled multiset of 79 labels in `1..11`
  and 58 zeros.
- For each challenged round (`b_i = m ≠ 0`), the response leaks the **sorted image set**
  `R_i = sorted( p_m[ p_{t,i}[Π_i[j]] ] for j in range(k) )`. Equivalently
  `R_i = p_m(V_i)` where `V_i` is the nonce's information set. **Ordering and diagonal
  multipliers are discarded.**
- The seed tree opens exactly the canonical minimal cover of the 58 zero-challenge rounds
  (`cvr({i : b_i = 0})`), revealing those 58 nonce seeds and none of the 79 challenged
  ones.

The provided toolkit reimplements every primitive faithfully:
`lim.py` (exact primitives + fast numpy `GF(127)` linear algebra),
`generate.py` (a numpy re-implementation that additionally dumps
ground-truth secrets/nonces for study), and the recovery pipeline
`keyrec.py` / `validate_pipeline.py`.

An extensive triage confirmed the capture is **byte-consistent with an honest run in every
publicly checkable way**: `sch(cmt)` reproduces each path's zero-set exactly; disclosed
leaves equal the zero-set (0 challenged leaves leaked); all 237 responses are sorted,
distinct, valid 274-subsets and information sets of their `PK_m`. Crucially, a proof shows
that with `V` an independent uniform random 274-subset, `R = p_m(V)` is **statistically
independent of `p_m`**, so `I(responses; p_m) = 0`. The responses alone carry zero
information about the secret permutations.

## Vulnerability / Core Concept

Since the response-only channel is provably zero-information, the flag can only be
recovered if, for some challenged rounds, the nonce information set `V_i` becomes
**computable / non-innocent** rather than a fresh independent random subset. The flag
states the fault directly:

> **`iteration skip makes no innocent response`**

An **iteration-skip fault** in the signing loop makes a challenged round's response leak
its `V_i`: once `V_i` is known for a challenged round, the pair `(V_i, R_i = p_m(V_i))` is
a direct constraint on the secret permutation `p_m`. Collecting enough such pairs for one
label pins down `p_m`, after which the secret diagonal follows algebraically from the
public `G0`/`PK_m` relation. (The exhaustive negative results in `analysis.md` rule out
every seed-tree, neighbor-leaf, stale-challenge and tree-independent-nonce variant, which
is why the fault must live in the challenged-round response computation itself: exactly
what the flag describes.)

## Exploitation

Once trustworthy `(V_i, R_i)` pairs are available for a label `m`, the recovery pipeline in
`keyrec.py` reconstructs the secret and the vault key. This pipeline is
**validated end-to-end** against a known-secret run generated by
`generate.py` (see `validate_pipeline.py`: it
recovers `ckey` exactly and matches the true vault key):

1. **Permutation from image sets**: `recover_perm(pairs)`: for each column `x`, its
   membership signature across the `(V, R)` pairs (a bitmask of "is `x ∈ V_bit`") must
   match a unique column `y` on the `R` side; unique matches give `p_m(x) = y`. About
   15-21 consistent pairs per secret resolve the full permutation (3 transcripts supply
   ~21 challenged rounds per label). Note: the per-label signature has a large noise floor
   below ~15 pairs, so only ≥15-pair matches are trustworthy.

2. **Diagonal from the public relation**: `recover_ckey(p_m, PK_m, G0)`: with `p_m`
   known, systematicize `G0` on the permuted columns to get `C = B_L^{-1} B_R`; then
   `PK_m[a][c] = (d_R[c]/d_L[a])·C[a][c]` is a bipartite ratio system solved by BFS over
   the ratio graph (fix `d_L[0] = 1`). This yields the diagonal up to the same global
   scale that `ckey` normalizes away.

3. **Canonicalize + derive the vault key**: `ckey` each secret (keep `p`, rewrite the
   diagonal into output-coordinate order, normalize first entry to 1), serialize all 11
   keys as little-endian `uint16` permutation entries + diagonal bytes, and
   `vkey = SHA256(b"vault|" + serialization)[:16]`.

4. **Decrypt the vault**: the 16-byte `vkey` is the AES-GCM key. GCM authentication over
   the published `nonce`/`ct`/`tag` gives a definitive check, and decryption yields the
   flag.

The `recover_perm → recover_ckey → vkey` chain is the load-bearing, verified part
(`keyrec.py` self-tests it against `generate.py`'s ground truth). Reproduction requires
running `generate.py` first to produce the known-secret reference dumps, then
`validate_pipeline.py`.

## Key Takeaways

- Image-set responses in a code-equivalence signature are **information-theoretically
  zero** about the secret permutation *when the underlying set is fresh and independent*: a fact worth proving before hunting for the actual leak.
- The exploitable channel is the pair `(V, R = p_m(V))`: a computable `V` for challenged
  rounds turns the "innocent" response into a hard constraint on `p_m`.
- Given `(V, R)` pairs, **membership-signature matching** recovers the permutation and the
  public `G0`/`PK` relation recovers the diagonal via a ratio-graph BFS: a clean,
  reusable LESS/LEP key-recovery pipeline.
- Calibrate any per-label matching metric against a random baseline; below the pair count
  where signatures become unique, apparent "matches" are pure coincidence.
